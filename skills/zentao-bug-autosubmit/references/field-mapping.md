## 设备名 / 系统名（2026-10-27 新增规范）

`——` 后面**先写设备名（APK/IGW）或系统名（PC），再写缺陷标题**，空一格分隔：

| 端 | 正确标题 |
|---|---|
| PC | `测试PC端——智慧后勤系统 在线用户列表接口匿名可访问` |
| APK | `测试APK端——出入库秤 同步进度文案与进度矛盾` |
| APK | `测试APK端——体脂秤 完善基础信息年龄可输入 999` |
| IGW | `测试IGW端——智能网关 配置接口未鉴权` |
| attack | `【高危】网络安全攻防——智慧后勤系统 xxx`（仅显式给设备名才加，老单格式不变） |

**两个来源，优先级从高到低：**

```
CSV 的「设备名」列（逐条，混设备必用）
   ↓ 没有这一列 / 该行为空
config.devices[端类型]（按端兜底，如 {"PC":"智慧后勤系统","APK":"体脂秤","IGW":""}）
   ↓ 都没有
不加设备名（退化成 <前缀>——<标题>）
```

- 列名也认：`设备名` / `设备` / `终端名称` / `系统名` / `所属系统` / `系统`。
- JSON 入口的键：`device` / `设备名` / `设备` / `系统名` / `system`。
- 三条去重：标题已带前缀只补插设备名；标题本身以设备名开头（「体脂秤一键测量用例超时」）不再重复拼；设备名为空则退化。
- **查重逻辑同步改了**：比对前先剥掉设备名，否则同系统标题前 12 字全一样、会被全判成重复（见 pitfalls 第 16 条）。

## 端类型（标题前缀）四档怎么选

标题前缀**四档都在脚本里**，不是只写死「网络安全攻防」：

| 端类型 | 生成的前缀 | 归一化认的写法 |
|---|---|---|
| `PC` | `测试PC端——` | PC / pc / PC端 / 测试PC端 / 电脑端 / WEB |
| `APK` | `测试APK端——` | APK / 安卓 / 安卓端 / APP / 移动端 / 手机端 |
| `IGW` | `测试IGW端——` | IGW / IGW端 / 网关 / 智能网关 |
| `attack` | `【X危】网络安全攻防——` | 攻防 / 攻击 / 安全 / 渗透 / 网络安全攻防 / 留空 |

X 由该条 `严重程度` 决定：`严重→【严重】`、`高→【高危】`、`中→【中危】`、`低→【低危】`；严重程度缺失时用 `config.attack_default_level`（默认中危）。

**取值优先级（逐条覆盖全局）：**

```
CSV 的「端类型」列（逐条）
   ↓ 没有这一列时
命令行 --end PC|APK|IGW|attack（本次运行临时覆盖）
   ↓ 没给时
config.end（全局兜底，本现场 = attack）
```

- **混合清单**（一份 CSV 里既有 PC 端又有 APK 端又有攻防）：加一列 `端类型` 逐条填，脚本各打各的前缀。
- 列名也认：`端类型` / `终端` / `所属端` / `测试端` / `端`。
- 标题里**已经带了规范前缀**（`测试PC端——`/`【高危】网络安全攻防——`）的不会被重复加。
- `--dry-run` 会打印实际分布，例：`端类型：测试PC端 2条 / 测试APK端 2条 / 测试IGW端 2条 / 网络安全攻防 2条`。
