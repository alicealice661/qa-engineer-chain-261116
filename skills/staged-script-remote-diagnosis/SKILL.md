# 分段脚本远程排障（Agent 不能直连目标机时）

## 链路位置（本包 qa-engineer-chain，先看这段再动手）

- **上一棒**：目标机 SSH / 网络不可达，必须靠用户手工执行脚本、截图回传。
- **本技能**：把排障写成 A~F 分段脚本 —— 每段只取一类证据、自带判断依据、危险操作条件化、改前备份并给回退。
- **下一棒**：证据 → 缺陷单（`zentao-bug-autosubmit`）或交付文档；配置类结论接 `springboot-jar-config-reverse`。
- **别用本技能做**：① 能直连的机器 → 直接跑，分段脚本是降级方案；② 只是拉一个分享链接的文件 → `seafile-anon-share-download`。
- **红线**：每段必须可单独执行、单独判断；`rm`/`mv`/重启类动作必须带条件判断与备份路径，不许裸执行。

## 何时用

- 目标机在内网 / 只能跳板访问，Agent 侧 `nc`/`ssh` 不可达
- 用户愿意配合执行、但只会"粘贴一条命令 + 截图"
- 需要连续多轮推进（部署 → 排错 → 验证 → 取证），每轮都要拿结果

判断信号：Agent 侧探测目标端口失败（`bash -c 'cat < /dev/null > /dev/tcp/host/port'` 超时），
但用户能贴回命令输出 —— 那就是这个模式，**不要反复尝试直连，直接开始写分段脚本**。

## 六条设计原则

1. **分段，不是流水**。一段 = 一个证据主题（A 环境 / B 取证 / C 改动 / D 重启 / E 汇总 / F 落盘）。
   用户截图天然按段对齐，回传后能逐段判读。
2. **只读段先行**。A/B 段只取证、绝不改状态；改动放 C 之后。
   这样即使脚本中断，也拿到了诊断信息。
3. **输出自解释**。每段不只要打印数据，还要打印"这说明了什么"：
   ```bash
   echo "  → 两个 md5 相同 = 同一份 jar；不同 = 容器跑的是别的版本"
   ```
   用户截图回来，Agent 和用户读的是同一句话，不会各说各话。
4. **危险操作条件化**。只在"确认必要"时才动：
   ```bash
   if iptables -t nat -S DOCKER >/dev/null 2>&1; then
       echo "  DOCKER 链存在，无需重启 docker"
   else
       echo "  DOCKER 链丢失 → 重启 docker（会短暂影响同机其他容器）"
       systemctl restart docker
   fi
   ```
   共享机器上尤其重要（同事在跑的容器不能无故被打断）。
5. **可逆 + 幂等**。改配置前 `cp` 备份到 `<dir>.bak-stepN`；插入而非覆盖用
   `grep -q ... || sed -i ...`；脚本末尾必给一行回退命令。
6. **结尾点名要哪几段**，不要"请把全部截图发我"（截图多了会漏关键段）：
   ```bash
   echo "完成。请把 A2 / C / E2+E4 截图发回。"
   ```

## 脚本骨架

```bash
#!/bin/bash
# ============================================================
# stepN：<一句话目标>
# ------------------------------------------------------------
# 为什么要有这一步：<上一步的结论 / 本步要回答的问题>
# 本步：A 体检 → B 取证 → C 改动（含备份）→ D 重启 → E 汇总 → F 落盘
# 用法：拖到目标机 /root/ → chmod +x stepN_xxx.sh → ./stepN_xxx.sh
# ============================================================
set -u                     # 不要用 -e：某段失败也要继续跑完
LINE="============================================================"
SUB="------------------------------------------------------------"

echo "$LINE"; echo "A. <主题>"; echo "$LINE"
...
```

- 用 `set -u` 而非 `set -e` —— 分段脚本要"跑完全程"，
  一段命令失败不能让后面的证据段全丢。
- 变量集中在文件头（路径 / 容器名 / 端口 / 命名空间），便于下一轮改。
- 需要用户等待时给出预估并合并 `sleep`（例：4 个服务 × 42 s = 约 3 分钟）。

## 三件套：定身份 / 定版本 / 定时间线

这三条几乎每个排障脚本都用得上，能消灭"猜"：

| 目的 | 命令 | 为什么不可替代 |
|---|---|---|
| **定身份**（本机到底是哪台） | `echo $SSH_CONNECTION` / `hostname -I` / `ip -4 addr` | `SSH_CONNECTION` = `客户端IP 客户端端口 服务端IP 服务端端口`，**服务端 IP 就是本机被连进来的地址** —— 多机环境里"笔记记的 IP"经常是错的 |
| **定版本**（跑的是不是我手里这份） | `docker exec <c> md5sum /path/app.jar` 与本地对比；`docker image inspect <img> -f '{{.Created}}'` | 结论与报错都基于"某一版"，版本没对齐就会误判病因 |
| **定时间线**（机器中途重启过没） | `uptime -s` / `journalctl --list-boots` | 一眼看出"服务莫名消失"是不是宿主机重启导致（配合 MySQL 的 `Database was not shutdown normally`） |

## 常见段落速查

| 段 | 用途 | 要点 |
|---|---|---|
| 环境体检 | 磁盘 / 内存 / OOM / load | `df -h`、`free -h`、`dmesg -T \| grep -i oom`、`uptime` —— 先排除资源问题，省得在配置上绕圈 |
| 容器取证 | 退出码 / 日志 / 环境 / 挂载 | `docker inspect -f '{{.State.ExitCode}} {{.RestartCount}}'`；crash-loop 看 `RestartCount`；**失败摘要只抓最后一个 `Caused by`** |
| 网络体检 | iptables / firewalld / 端口 | `iptables -t nat -S DOCKER`（链丢没丢）、`systemctl is-active firewalld`、`ss -tlnp` |
| 配置改动 | 补键 / 重写 | 先 `cp -f` 备份；用 `heredoc` 在目标机直接生成文件（免传文件）；改完立刻"关键字命中校验"，不要比字节长度 |
| 逐项验证 | 单点试水 | **先起 1 个最简服务**验证链路，通了再批量；给单点 `--restart=no` 防空转烧 CPU |
| 汇总 | 期望值对照 | 明确写出期望（"期望 count=7"），让截图自己回答成不成立 |
| 落盘 | 素材沉淀 | 把本轮关键输出写进 `/home/<user>/handbook-stepN.txt`，供后续写文档直接引用 |

## 需要外部服务时

脚本里直接调 API 比让用户手工点界面可靠：

```bash
TOK=$(curl -s -m 10 -X POST "http://127.0.0.1:18850/nacos/v1/auth/login" \
      -d "username=nacos&password=nacos" | sed -n 's/.*"accessToken":"\([^"]*\)".*/\1/p')
curl -s -m 10 "http://127.0.0.1:18850/nacos/v1/ns/service/list?...&accessToken=$TOK"
```

`curl -s -m <秒>` 一定要带 `-m`：目标机网络不通时不能挂住整段。

## 只读脚本（体检/取证类）发布前的四道自检

出「只读体检」脚本让用户在**共享生产机**上跑时，光说"只读"不够，得让脚本自证：

**① 把边界写进脚本头，逐条列「不做哪些事」** —— 用户才敢跑、才敢整段回传：

```bash
# 严格的只读边界（脚本内绝不会做这些事）：
#   × 不写 /etc/yum.repos.d/        （只 cat / ls，不 mv、不新建）
#   × 不执行 yum makecache / update （只跑 yum repolist -C，仅读本地缓存）
#   × 不改 sshd 配置、不重启任何服务
#   × 不显示任何口令明文            （口令只查「最后修改日期」，不查内容）
```

**② 用一条正则反查写操作**，命中即人工复核（只应命中注释行）：

```bash
grep -nE "sed -i|>\s*/etc|>>\s*/etc|mv |rm |mkdir |yum (makecache|clean|update|install)|\
systemctl (restart|start|stop)|firewall-cmd --(add|remove|permanent)|passwd |chmod |chown" stepN_*.sh
```

**③ 本地干跑，验证「能跑到最后一行」** —— 目标机是 Linux，但脚本可先在本机
（Windows Git Bash / macOS）整跑一遍：环境相关的段会大量打印"无 / 未取到"，
而这正好验证了**分支降级路径**是否健壮。比只做 `bash -n` 强得多 ——
语法过不代表运行不崩（未定义变量、空数组、除零都在运行时才炸）：

```bash
bash -n stepN_xxx.sh && bash stepN_xxx.sh 2>&1 | tail -3   # 末行应见「=== stepN 结束 ===」
```

**④ 警惕两种"看起来只读"的命令**：`yum repolist`（不带 `-C`）会联网下载元数据并
**写缓存**；`firewall-cmd --list-*` 只读、但 `--permanent` 就写了。要真只读就用
`yum -C`，并在脚本结论里明说：「最终证据需要你手工跑一次会写缓存的命令」。

**⑤ 把「取值」和「判定」分开自检**（最容易翻车的一步）：取值对了，判定仍可能自相矛盾。
实测反例：脚本 D 段已正确判出「同时监听 22 与 10022 → 加固未完成」，而 E 段汇总却只
`grep -q 10022` 就下「已加固到 10022」——**同一份脚本的两段结论互相打脸**，
用户拿着截图没法判断该信谁。

```bash
# 反例：只问"新端口在不在"，漏掉"老端口还开着"
verdict "$(echo "$SSHPORTS" | grep -q 10022 && echo '已加固' || echo '未做')"

# 正解：拆成两个布尔量，穷举三态
HAS22=$(echo " $SSHPORTS " | grep -q ' 22 ' && echo 1 || echo 0)
HAS10022=$(echo " $SSHPORTS " | grep -q ' 10022 ' && echo 1 || echo 0)
#   只在 10022        → 合格
#   两个都在          → 加固未完成（老端口没关）
#   只有 22           → 尚未开始
```

同类两条陷阱：

- **locale 会让取值静默失效**：`chage -l root | awk '/Last password change/'` 在中文系统上
  永远取空（输出是「最近一次密码修改时间」）。凡解析系统命令输出，一律加 `LC_ALL=C`。
  ⚠ 更危险的是：**取空后若判定写成 `[ -n "$X" ] && echo 好 || echo 坏`，会静默给出错误结论**
  —— 先确认取到值，再谈判得好不好。
- **「单点存在」不等于「状态合格」**：判断端口 / 服务 / 挂载这类状态，要穷举「哪些在」，
  而不是「某一个在不在」。

## 坑位

| 现象 | 原因 / 解法 |
|---|---|
| 脚本"改动段"报错后，后面的汇总段全没了 | 用了 `set -e`。分段脚本用 `set -u`，并让每段自带 `\|\| echo "(跳过)"` |
| 回读校验显示"失败"，但服务其实起来了 | 校验逻辑本身有 bug（例：`GET` 少了 `accessToken` 被 403、比的是 JSON 包裹体长度）。**以服务侧证据为准**（启动日志 / 注册列表），回头再修脚本 |
| 截图里 ✓ 看成 ✗ | 小字号对勾形似叉。判定前先读脚本里的分支逻辑（`&& hit="✓" \|\| hit="✗"`），别只凭截图 |
| 查物料的段返回"（无）"，但用户知道机器上有 | 查错目录。多路径并列找，或先 `ls` 打印目录列表再定位；**别用单一路径就下"没有"的结论** |
| 排查结论与手上文件对不上（文件名/类名冲突） | 先用 md5 定版本，再回头怀疑自己读低分辨率截图时的偏差 |
| 共享机器上重启 docker 影响同事 | 危险操作条件化（先判断是否真需要），并在输出里写明"会短暂影响同机其他容器" |
| 汇总段与明细段结论互相打脸 | 汇总的判定逻辑比明细段简单。**写判定要穷举状态，别只判"某一个在不在"**；明细段已有正确结论时，汇总段应复用它 |
| 取值为空却照样给出了结论 | locale 导致解析失败（中文 `chage` / `date` / `systemctl` 输出）。加 `LC_ALL=C`；并在取空时让判定显式报"未取到"，而不是落进 else 分支给结论 |
