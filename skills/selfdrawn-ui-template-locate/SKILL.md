# 自绘 UI 模板定位（多视觉态 + 阈值实测推导）

## 链路位置（本包 qa-engineer-chain，先看这段再动手）

- **上一棒**：`device-e2e-flow-driver` 或 `android-adb-test-monitor` 发现 `uiautomator dump` 拿不到控件（自绘渲染）。
- **本技能**：给出**可复用的模板匹配定位方案**（几何独立测量 → 变形/变色判定 → 阈值由分离间隔推导 → 连续两帧稳定才算命中）。
- **下一棒**：回到 `device-e2e-flow-driver`，把定位结果接进「判步 → 点击 → 双源断言」的状态机。
- **别用本技能做**：① dump 能拿到 `resource-id` → 直接 uiautomator，不必上模板匹配；② 判断「这个组件有没有用户入口」→ `android-component-entry-verify`（静态三线证据）；③ 只想点一下某坐标 → `adb input tap` 足够。
- **验收判据**：换背景/换分辨率仍命中才算跑通，单张图命中一次不算。

## 何时用

- 设备界面**自绘渲染**：`uiautomator dump` 只出几十字节空壳、**无 resource-id**
- 需要 `adb input tap` 但**禁止硬编码坐标**（坐标必须由匹配动态求得）
- 已有的模板匹配方案"**本机能命中、换个背景就掉**"
- 要回答"**定位到底跑通没有**"——不是能出分就算通，见下方验收判据

## 铁律（四条，都是踩过的坑）

1. **"全 1.000"是警报，不是好消息。**
   若一套方案在正样本上全是 1.000，**先做误报扫描**。典型：`Canny` 边缘匹配看似完美，实则边缘图 99% 为 0 → `TM_CCOEFF_NORMED` 去均值后分母趋零 → 虚高。识别标志：**负样本也全 1.000，且 peak 全落在 ROI 角落**。

2. **真实坐标不能从模板倒推。**
   模板从 (x,y) 裁出 → 匹配必然回 (x,y)，这是**循环论证**，不是测量。必须几何独立测量：扫描线亮度/梯度剖面、网格标定、圆拟合等。

3. **样本分类不能靠文件名，要靠独立裁判 + 目视归实。**
   用**另一个已证明零漂移的元素**（如稳定文本）当裁判来判定"当前是不是这个页面"。但要知道裁判会失效（弹窗遮挡）——高分/低分异常帧一律**目视确认归属**再下结论。

4. **阈值不能拍脑袋，要用分离间隔算。**
   取样本最高误报分与最低命中分的**中点**。若分离间隔 ≤0，方案不成立，别硬调阈值。

## 标准流程

### 步骤 1 · 判定是否真的需要模板匹配
先跑 `uiautomator dump` 看控件树。**若页面有原生控件（有 resource-id/bounds），直接 dump 取 bounds，不要用模板匹配**（原生控件的坐标是动态读的，天然合规）。只有自绘页才走这条路。

### 步骤 2 · 独立测量控件几何（先测，后裁）
```python
# 扫描线剖面：找控件边界的交点 → 算中心
# 竖直扫描给 y，水平扫描给 x；多种子区域求众数，剔除背景噪声边缘
# 再叠加"网格标定图"目视复核（画坐标网格 + 候选点十字）
```
**必须两个独立方法互证**，且把结果写进档案的 `geometry`（不要写进 `observed_box` 当成"仅供复核"后就忘了）。

### 步骤 3 · 先判断"变的是形状还是配色"，再决定要不要多模板

> **别急着建多模板。** 先分清控件属于哪一类 —— 这决定模板数量，判错会白做一堆模板。

**A 类：只变配色/亮度，形状不变**（纯色底 + 文字/图标的按钮、选项标签、方形标签块）
- → **单模板即可**。`cv2.TM_CCOEFF_NORMED` 是**零均值**归一化互相关，对**整体亮度/色彩偏移天然免疫**，只认形状。
- 实证（2026-09-28）：第3步 A 选项标签的模板**从蓝色高亮态裁**，实机是**灰色未高亮态** —— 仍命中 **NCC 0.9782**，坐标零漂移。
- 结论：**不必为每个配色态分别建档**，省掉一半工作量。

**B 类：形状本身变化**（半透明控件与背景混色、背景轮播导致纹理重组）
- → **必须建多模板**。典型：主页「开始晨检」按钮**半透明**，观感 = 自身色 × 透明度 + 背景色 × 透光，背景一换像素就分簇（跨簇互相关 ≤0.556）。
- 自检：算控件区域内的 `std` 与亮像素占比。若某态 **std 极小（如 6）+ 亮像素 0%** → 该态**前景信息已物理丢失**，任何纹理匹配都无解，只能靠轮廓/多模板。

**通用判簇手法**：对同一控件收集**多个不同时期/不同背景**的样本，两两算 NCC，看是否**聚成簇**（簇内 ≥0.8、跨簇 ≤0.6）。但**判簇后仍要回上面分类**：A 类样本可能因背景导致轻微分簇，加一个模板就够；B 类才是真的形状重组。

### 步骤 4 · 建档（多模板几何同源）
```bash
PY=".../envs/default/Scripts/python.exe"     # 需带 cv2 的解释器

# 所有视觉态模板都用同一个 box 裁 → peak 中心天然一致，与命中哪套模板无关
"$PY" tools/ui_locate.py crop --src <暗态基准图> --box x1,y1,x2,y2 --out templates/controls/<名>_dark.png
"$PY" tools/ui_locate.py crop --src <亮态基准图> --box x1,y1,x2,y2 --out templates/controls/<名>_light.png
```

**⚠️ 用 ROI 分割挡住"串位"**：整块按钮模板含大面积底色，跨态匹配会**跑到位移邻居身上** —— 实测「正常上岗」模板在右侧「离岗休息」位置得 **0.933**（两者只有底色不同）。修法：**按各自矩形切分 `roi`**（左半 / 右半各搜各的），串位即消除。定位前先做一次"跨态互查"，看高分是否落在**别的控件位置**上。

### 步骤 4b · 动画/过渡帧必须"连续两帧稳定"才算数
页面**冷启动或背景淡入期间**存在过渡帧，控件可能**尚未渲染完成**。实测：`force-stop` 重启后主页按钮 NCC 从稳态 **0.81~0.90 骤降到 0.5711**（低于阈值）。单帧判定会被过渡帧骗到。
**修法**：定位循环要求**连续 N（≥2）帧命中**才返回坐标，N 帧之间不满足即清零重来。

### 步骤 5 · 用独立裁判分类样本，算分离间隔定阈值
```python
# 用另一零漂移元素当裁判 → 分 POS/NEG → 逐个算控件分
POS min = ...   # 命中最低分
NEG max = ...   # 误报最高分
分离间隔 = POS min - NEG max
阈值 = (POS min + NEG max) / 2      # 分离间隔 ≤0 则方案不成立
```
把**推导过程**写进档案（`_threshold_basis`），后来的维护者才知道这个数不是拍的。

### 步骤 6 · 验收判据（"跑通"的定义）
| 判据 | 合格线 |
|---|---|
| 跨帧回归 `selftest` | **全 PASS**，且命中坐标一致（±tol） |
| **误报扫描 `sweep`** | 非目标页面**零命中**；目录里混入局部截图不得**崩溃** |
| **实时端到端** | 连测 ≥10 次**全命中**，坐标抖动 ≤2px |
| **实时 NCC 分布** | 最低分**明显高于阈值**（不是压线通过） |
| 单模板对照 | 必须给出"若只用单模板会漏检"的实证（说明多模板的必要性） |

> **压线通过 = 没跑通**。修复前实测 0.5905 / 阈值 0.60，看着"差一点"，实则**直接拒绝点击**。

## 可复用脚本骨架

`tools/ui_locate.py`（本技能配套实现，6 个子命令）：

| 命令 | 作用 |
|---|---|
| `list` | 列出已建档控件（含模板数） |
| `crop --src --box --out` | 建档；`--out` 支持元素未定义时直接落盘（做多视觉态模板） |
| `locate <img> <name> [--debug]` | 单图定位 + 标注图 |
| `tap <name> [--dry-run]` | 实时截图 → 定位 → 点击；**不达门限拒绝点击** |
| `selftest` | 跨帧回归（档案里 `regression.expect_hit/expect_miss`） |
| `sweep <dir> <name>` | 误报面扫描（**必须逐张容错**，否则一张局部截图能打断整批） |

关键实现要点：
- **多模板**：元素配 `templates: [...]`，逐个匹配**取最高分**
- **灰度匹配**（默认）：对亮度/色偏更鲁棒；对纯文本元素零损失
- **边界检查**：`img` 小于 `roi` 时裁剪会得到**空数组**，必须在 `matchTemplate`/`cvtColor` **之前**挡掉
- 图像 IO 走 `np.fromfile + cv2.imdecode`（cv2 不支持非 ASCII 路径）

## 已排除的路线（不要重走）

| 方案 | 失败表现 |
|---|---|
| `Canny` 边缘 + `TM_CCOEFF_NORMED` | 全帧虚高 1.000（退化匹配），分离间隔 0.000 |
| `HoughCircles` | 主页帧 **0 检出**，`param1/param2/dp` 极敏感，不适合生产 |
| 单模板 + 降阈值硬扛 | 跨态时必然有一侧漏检（实测单模板最低 0.581，双模板 0.773） |
| 用 `equalizeHist` 压平亮暗态 | 反而**破坏信息**，NCC 更低（实测 0.488） |

## 常见坑

- **归档时删文件**：本机回收站**只留 `$I` 元数据、不留 `$R` 实体** → 删即不可恢复，动手前先确认。
- **`adb shell wc -l` 计数失真**（曾得 147 vs 真值 35）→ 一律用 `adb exec-out`。
- **托管 Python 常无 cv2** → 用 `~/.workbuddy/binaries/python/envs/default/Scripts/python.exe`。
- **文件名不可靠**：截图批次命名与内容可能不符（`entry_version` 实为主页）。**先目视，再定性。**
